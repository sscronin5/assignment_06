3. Where did you struggle
I struggled most with debugging failed API calls. At first, when a request failed, my code kept going
 and broke later with a confusing error about a missing key. Then I learned that calling 
 raise_for_status() right after the request stops the code at the actual problem and shows 
 the HTTP status code. That’s how I could tell a 401 (bad or missing API key) from a 429 (rate limit). 
 I also struggled in aspects.py with getting the opinion mining and named-entity recognition results 
 into a clean table. The entities and their mentions were nested a few levels deep, and I kept getting 
 the wrong grain: one row per document when I needed one row per mention. Finally, I wasted API calls 
 by re-running the same requests over and over while testing. That’s the problem caching solves, and 
 I should have set up caching earlier instead of hitting the API every time.
